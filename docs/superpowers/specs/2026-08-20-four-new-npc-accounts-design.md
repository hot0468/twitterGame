# NPC 계정 4개 추가 — 아이돌 현장·극장·행정 안내·살림

날짜: 2026-08-20

## 배경

계정 20개에 4개를 더한다. 요청은 "아이돌 덕질 / 영화 리뷰 / 생활정보" 셋이었고,
생활정보를 두 갈래(행정 안내 · 살림 꿀팁)로 나눠 넷이 됐다.

세 요청 모두 기존 계정과 소재가 겹친다. 그래서 **소재가 아니라 거리와 말투로 가른다** —
애니 3계정(`@anime_burn` `@otaku_wallet` `@sakuga_note`)이 같은 소재를 세 거리에서
다루는 것과 같은 방식이다.

| 요청 | 겹치는 기존 계정 | 가르는 축 |
|---|---|---|
| 아이돌 덕질 | `@anime_burn`(과열) `@otaku_wallet`(자조) | **몸으로 겪는다** — 애니 3계정은 전부 방에서 본 것을 쓴다 |
| 영화 리뷰 | `@spoiler_free`(감상만) `@sakuga_note`(연출 분석) | **내용 바깥만 쓴다** — 노스포러가 못 말하는 내용을 아예 다루지 않는다 |
| 생활정보 | `@info_hunter`(수집) `@sat_review`(장소 리뷰) | **기한이 있다** / **직접 해본다** |

| 좌석기록 | `@seat_log` | 무슨 관에서 봤는지까지 적습니다. 내용은 안 적습니다. | 4700 | `["daily","info"]` | 관람 기록체 — 관·좌석을 먼저 적고 시작 |
| 마감안내 | `@notice_kr` | 기한 있는 것만 알려드립니다. 비공식입니다. | 33500 | `["info"]` | 공고문체 — 마감일 명시, "~하시기 바랍니다" |
| 살림해보는중 | `@home_tips` | 살림 팁 모아요. 반은 실패합니다ㅎㅎ | 8900 | `["info","daily"]` | 다정한 조언체 |

### 말투 중복은 허용한다

`@home_tips`의 다정한 조언체는 `@mutuals_only`(다정한 해요체+ㅎㅎ)·`@cat_daily`(다정한 반말)와
결이 가깝다. **내용이 다르면 말투가 겹쳐도 된다**는 판단이다 — 이 계정은 살림 팁이라는
구체적 정보를 다루므로 잡담 계정과 트윗이 섞이지 않는다.

### reactsTo와 스탯

첫 카테고리가 반응 스탯을 정한다(`attrStat`: humor→유머 / info→글빨 / daily→감각 / bait→논란성).

- `@stage_run` `@seat_log` → **감각**
- `@notice_kr` `@home_tips` → **글빨**

**넷 다 bait가 아니다.** 논란성은 쌓기 쉬우면 topStat 엔딩 3종이 막힌다(CLAUDE.md에 실측
기록이 있다 — 1일차 352회 반응에 논란성 +13). bait 계정은 3개로 유지한다.

추가 후 첫 카테고리 분포: humor 3 / info 8 / bait 3 / daily 10 (실측).

## 트윗

계정마다 **28개**. `timeline.gen.max`가 24이므로 여유 4개에서 매일 2개를 갈아넣는다 —
기존 20계정과 같은 관계이고 회귀 테스트가 이를 검사한다. `gen` 노브는 건드리지 않는다.

- 10~140자. 짧은 것(25자 이하)과 긴 것(90자 이상)을 각각 최소 하나씩.
- 줄바꿈은 데이터에 `\n`으로 직접 적는다.
- `{밈소재}`·`{떡밥}` 치환자를 계정마다 몇 개 섞는다(우측 레일 트렌드 집계 대상).
- 계정 간 중복 금지.
- `replies` 3개씩 — 내 트윗 상세의 스레드가 된다.

## 아바타

`assets/avatars/`에 핸들과 같은 이름의 svg 4개: `stage_run.svg` `seat_log.svg`
`notice_kr.svg` `home_tips.svg`.

경로는 데이터에 적지 않는다 — `ui.js`의 `pfp()`가 핸들에서 만든다. 기존 22개와 같은
DiceBear open-peeps(CC0)를 받아 **저장소에 커밋해서** 쓴다. 런타임에 외부 URL을 부르지 않는다.
받는 방법과 배경색 표는 `assets/avatars/README.md`.
