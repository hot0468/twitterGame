# 트위터 UI 육성 게임 — 설계 문서

날짜: 2026-08-17

## 개요

트위터 UI를 차용한 턴제 육성/경영 게임. 플레이어는 자기 계정의 주인으로서 트윗과 자기계발로 스탯을 키우고 팔로워를 늘린다. 타임라인은 NPC와 사건으로 살아 움직이며, 팔로워 수가 임계값에 도달하면 스탯과 행적에 따라 멀티 엔딩으로 분기한다.

## 확정된 핵심 결정

| 항목 | 결정 |
|------|------|
| 컨셉 | 인플루언서 육성 + 살아있는 타임라인 시뮬레이션 (A+C) |
| 시간 진행 | 턴제 — 하루 = 1턴 |
| 엔딩 | 팔로워 수 임계값 도달 시 스탯·이벤트 이력으로 멀티 엔딩 판정 |
| 콘텐츠 | 뼈대(사건·수치·분기)는 JSON 데이터, 텍스트는 템플릿+치환. LLM은 나중에 얹을 수 있는 구조만 유지 |
| 플랫폼 | 웹 브라우저, 바닐라 JS, 빌드 도구 없음, localStorage 저장 |

## 1. 게임 루프

하루(1턴)의 흐름:

1. **아침 — 타임라인 확인**: 밤사이 쌓인 피드(NPC 트윗, 어제 트윗의 반응, 이벤트)를 본다.
2. **행동 선택 — 단일 입구**: 컴포즈 박스("무슨 일이 일어나고 있나요?")를 누르면 오늘 가능한 행동이 전부 한 목록으로 나온다.
   - 트윗 카테고리 (유머 / 정보글 / 일상 / 떡밥 참전 …)
   - 자기계발 (글쓰기 연습 / 트렌드 조사 / 휴식 …) — 결과가 자동 트윗으로 표현되어 세계관 유지
   - 진행 중 이벤트 대응 선택지 (있을 때만 맨 위 강조)
   - **하루에 행동 하나.** 고르면 결과가 피드에 추가되고 "다음 날" 버튼 활성화.
3. **정산**: 팔로워·스탯 변동 표시 후 다음 턴.

## 2. 스탯 (5종)

| 스탯 | 올리는 법 | 효과 |
|------|----------|------|
| 글빨 | 글쓰기 연습 | 모든 트윗의 기본 반응량 증가 |
| 유머 | 밈 공부 | 유머 트윗 성공률·확산력 |
| 감각 | 트렌드 조사 | 떡밥 타이밍 판정, 행동 해금 |
| 멘탈 | 휴식 | 악플/논란 피해 감소. 0이면 강제 휴식(턴 손실) |
| 논란성 | 어그로성 선택 시 자동 상승 | 팔로워 급증 + 나쁜 이벤트 확률 증가 (양날의 검) |

핵심 긴장: **논란성은 성장 가속 페달이지만 엔딩과 이벤트를 나쁘게 굽힌다.** "빨리 큰 계정"과 "잘 큰 계정"이 달라지는 것이 게임의 축.

## 3. 콘텐츠 데이터 (JSON 4종)

엔진은 로직만 알고 내용물은 전부 데이터. **콘텐츠 추가 = JSON 항목 추가, 코드 수정 없음.**

### actions.json — 행동 정의

```json
{
  "id": "tweet_humor",
  "type": "tweet",
  "label": "유머 트윗",
  "requires": { "감각": 10 },
  "effects": { "팔로워": "유머*3 + 글빨", "논란성": 0 },
  "templates": ["오늘 지하철에서 본 건데 {밈소재}...", "..."]
}
```

- `requires`: 스탯 해금 → 육성 보상이 눈에 보임
- `effects`: 스탯 기반 수식. 자기계발은 팔로워 대신 스탯 상승
- `templates`: 랜덤 선택 + 빈칸 치환으로 텍스트 다양화

### npcs.json — 등장 계정

핸들, 프로필, 성향(반응하는 카테고리), 말투 템플릿. 배경 트윗과 내 트윗 리플의 출처.

### events.json — 사건 (게임의 심장)

```json
{
  "id": "viral_backlash",
  "trigger": { "논란성": ">=30", "chance": 0.3 },
  "stages": [
    { "feed": ["{npc:빅계정}이 내 트윗을 인용하며 저격했다"],
      "choices": [
        { "label": "사과문 올리기", "effects": { "팔로워": -200, "멘탈": -5 }, "next": "끝" },
        { "label": "맞받아치기", "requires": { "멘탈": 40 }, "next": "stage2" }
      ] }
  ]
}
```

- 트리거: 스탯 조건 + 확률 + 팔로워 구간. 논란성이 높으면 나쁜 이벤트 풀 활성화
- 다단계 진행(오늘 저격 → 내일 대응 → 모레 결과)으로 "살아있는 타임라인" 구현

### endings.json — 엔딩 조건

팔로워 임계값 도달 시 판정. 조건 = 스탯 조합 + 이벤트 이력.
예: 팔로워 10만 도달 → 논란성 50 이상 "사이버렉카" / 글빨 최고 스탯 "등단 작가" / 조건 미달 "그냥 유명한 사람".

## 4. 화면 구조 (3개)

좌측 네비게이션(홈/알림/프로필)으로 전환. DM·검색·트렌드는 첫 버전 제외(추후 이벤트 연출용 확장 여지만 유지).

- **홈(타임라인)** — 게임의 90%. 상단에 N일차 + 팔로워 수 상시 표시. 컴포즈 박스 = 행동 입구. 피드에 내 트윗·반응 수치·NPC 리플·이벤트 트윗(강조)·자동 트윗이 최신순으로 쌓임.
- **프로필** — 트위터 프로필 페이지 모사. 자기소개 아래 스탯 5종("글빨 Lv.7" 식) + 내 트윗 이력.
- **알림** — 이벤트 로그. 대응 필요 이벤트가 있으면 탭에 뱃지.

## 5. 파일 구조

```
twitterGame/
├── index.html
├── css/style.css          # 트위터풍 스타일 (다크 테마 기본)
├── js/
│   ├── engine.js          # 턴 진행·스탯 계산·이벤트 판정·엔딩 판정 — 순수 로직, DOM 모름
│   ├── ui.js              # 렌더링·클릭 처리. engine 결과를 그리기만 함
│   └── main.js            # 초기화, 데이터 로드, 저장/불러오기
├── data/
│   ├── actions.json
│   ├── npcs.json
│   ├── events.json
│   └── endings.json
└── test/sim.js            # 자동 플레이 시뮬레이션 (밸런스 검증)
```

## 6. 엔진-UI 계약

엔진의 공개 인터페이스는 `advanceTurn(actionId)` 하나:

```
advanceTurn(actionId) → { feedItems, statChanges, triggeredEvents, ending | null }
```

UI는 반환값을 그리기만 한다. 이 경계 덕분에 UI 교체나 LLM 텍스트 생성 추가가 엔진 수정 없이 가능.

## 7. 저장

- localStorage 자동 저장 (매 턴 종료 시)
- 저장 내용: 스탯, 팔로워, 날짜, 이벤트 이력, 내 트윗 로그
- "새 게임" 버튼으로 초기화

## 8. 검증

engine.js는 DOM을 모르므로 Node에서 직접 실행 가능. `test/sim.js`로 100턴 자동 플레이를 돌려 엔딩 도달 여부, 스탯 음수 방지 등 밸런스를 숫자로 확인한다.
