# 스토리 DM 둘 — 첫 팬, 길고양이

날짜: 2026-08-20

## 배경

스토리 DM이 둘 있다(괴담계 `@old_records`, 습작 `@rookie_writer`). 둘 다
**남의 사연을 들어주는** 구조이고, 게임 전체가 어두운 쪽으로 기울어 있다 —
괴담은 폐교에서 끝나고, 쓰다가지움은 매일 지우는 계정이고, 엔딩엔 사이버렉카와
빚쟁이 스타가 있고, 최근 추가한 것도 저격(인용)과 박제(삭제)다.

여기에 갈등을 더 얹으면 폭이 넓어지는 게 아니라 한 방향으로 더 쌓는 것이다.
그래서 이번 둘은 **나쁘게 끝나지 않는** 이야기다.

## 1. 첫 팬 — `@mutuals_only`

**조건**: `팔로워 >= 3000` + 그 계정 트윗 반응 3회

**왜 이 계정인가**: 맞팔 100%에 "조용히 서로 응원하는 사이"라는 bio.
다정한 해요체 + ㅎㅎ 말투가 이미 확립돼 있다.

**왜 이 이야기인가**: 기존 둘이 "남의 사연"이라면 이건 **내 이야기**다.
게임에서 팔로워는 계속 숫자로만 나온다(10 -> 100만 카운터). 이 이야기는 그
숫자 하나에 사람을 붙이고, **플레이어가 실제로 겪은 것**을 재료로 쓴다 —
진짜로 팔로워 10에서 시작했기 때문이다.

노드 7개. `f4`에 `delay: 2`(옛 트윗 캡처를 모아 보내는 시간).
결말 둘: `f5a` 고맙다(멘탈 +5) / `f5b` 지금도 똑같다(멘탈 +4, 감각 +2).
**더 말하는 쪽이 더 얻는다** — 괴담계가 "더 얻고 대가를 낸다"였다면 이쪽은 대가가 없다.

## 2. 길고양이 — `@cat_daily`

**두 단계 사슬이다.** 기존 스토리는 스탯만 보고 시작하는데, 이건
**실제 행동의 결과**로 열린다.

### 1단계 — 이벤트 `stray_cat`

`trigger: { action: "walk", chance: 0.3 }`

산책하기에는 이미 괴담계 `old_school`이 걸려 있다. 부딪히지 않는 이유는
저것이 `dmStory: "@old_records:s2"`라는 **아주 좁은 조건**이라 나머지 대부분의
산책에서는 아무 이벤트도 안 뜨기 때문이다. 그 빈자리를 쓴다.
(CLAUDE.md "같은 행동에 두 이야기를 걸지 말 것"은 **스토리**를 두 개 거는 것에
대한 규칙이고, 여기서는 조건이 겹치지 않으므로 어긋나지 않는다.)

선택지 셋:
- **트윗한다** -> `flag: "cat_tweeted"` + 팔로워 소폭
- 사진만 찍는다 -> 멘탈 +
- 그냥 지나간다 -> 효과 없음

### 2단계 — 스토리 시작

`requires: { flags: ["cat_tweeted"], chance: 0.35 }`

**"만났다"가 아니라 "그 얘기를 트윗했다"가 조건이다.** 만나고 그냥 지나치면
안 열린다. 그래서 `eventHistory`(겪었나)로는 안 되고 플래그가 필요하다.

**확률 0.35**: 기존 스토리는 조건이 맞으면 확정으로 시작하는데 이게 첫 확률 사례다.
길고양이는 원래 다시 만날지 알 수 없는 존재라 소재와 맞고, 확정이면
"트윗 = 스토리 시작"이라 기계적으로 읽힌다.

노드 6개. `c2`에 `delay: 2`(병원), `c3`에 `delay: 3`(검사 결과).
**연속된 침묵이 이야기의 본체다** — 기다리는 동안 방은 열려 있고 아무 표시도 없다
(기존 규칙 그대로. "기다리는 중" 같은 문구를 넣지 말 것).

결말 둘: `c5a` 다행이다(멘탈 +5) / `c5b` 뭉치는 어떠냐고 묻는다(멘탈 +4, 감각 +2).
**게임에서 유일하게 "걱정했는데 괜찮았다"로 끝난다.**

## 새 노브 둘

### `state.flags`

`{}`. 이벤트 선택지의 `flag: "이름"`이 찍고, 스토리 `requires.flags: [...]`가 읽는다.
범용이라 나중에 다른 이야기도 쓴다. 구버전 세이브 보정 대상이다(`create()`의 `missing`).

### `requires.chance`

조건이 맞아도 확률로만 시작한다. **없으면 확정(1.0)** — 기존 두 스토리가
그대로 동작해야 하기 때문이다.

`storyReady()`가 `reactions`를 따로 처리하듯 `flags`·`chance`도 `checkCond`에
넘기기 전에 걸러내야 한다. 안 그러면 스탯 이름으로 오해한다
(CLAUDE.md에 이미 `action`·`dmStory`로 같은 함정이 적혀 있다).

## 검증

`test/engine.test.js`:
- 이벤트 선택지가 flag를 찍는가
- `flags` 조건이 실제로 막는가(플래그 없이는 안 열린다)
- `chance`가 없으면 확정인가(기존 두 스토리 회귀)
- 두 이야기가 끝까지 진행되는가
- 보상이 한 번만 들어가는가(끝 노드는 done이 찍혀 다시 안 지나간다)
- 구버전 세이브에 `flags`가 없어도 터지지 않는가

기존 4개 스위트 전부 통과해야 한다.
