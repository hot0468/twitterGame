# 트윗 속성과 반응 스탯 — 설계

날짜: 2026-08-19

## 요약

NPC 트윗마다 **속성**이 하나 붙는다. 같은 속성의 트윗 **5개에 반응할 때마다**
그 속성에 대응하는 스탯이 **+1** 오른다. 트윗 하나는 딱 한 번만 센다.

속성은 트윗 우상단에 아이콘으로 표시되어 누르기 전에 무엇이 오를지 알 수 있고,
반응한 순간 누른 자리에 게이지 토스트가 떠서 5칸 중 몇 칸이 찼는지 보여준다.

## 배경

지금까지 남의 트윗 반응은 **스탯에 영향이 없었다**. 트윗 448개에 전부 누를 수 있어서
스탯을 주면 공짜 성장 경로가 되기 때문이다(CLAUDE.md "남의 트윗에 반응").

이 설계는 그 제약을 **트윗당 1회 상한**과 **논란성이라는 역방향 대가**로 대체한다.
반응은 여전히 하루를 소모하지 않는다.

## 1. 속성 모델

| 속성 (카테고리) | 스탯 | 아이콘 | 계정 수 |
|---|---|---|---|
| `humor` | 유머 | `laugh` | 3 |
| `info` | 글빨 | `feather` | 4 |
| `daily` | 감각 | `trending-up` | 6 |
| `bait` | **논란성** | `flame` | 3 |

**속성 결정 순서:**
1. 트윗에 개별 속성이 지정돼 있으면 그것
2. 없으면 그 계정의 첫 카테고리(`reactsTo[0]`)

계정 카테고리가 기본값인 이유는 이 게임이 이미 "계정 하나 = 컨셉 하나" 위에 서 있어서다.
유머 계정 트윗을 좋아요했는데 감각이 오르면 읽히지 않는다.

**`bait`은 논란성으로 간다 — 이 설계의 핵심이다.**
떡밥 계정을 챙겨보면 논란성이 쌓인다. 반응이 순수한 이득이 아니라 **선택**이 되고,
논란성은 이벤트 트리거이므로 게임이 실제로 반응한다. 무제한 연타의 자정 장치이기도 하다.

## 2. 데이터 표기 — 문자열/객체 혼용

`data/npcs.js`의 `tweets`는 문자열 배열을 유지하되, **예외인 트윗만** 객체로 적는다.

```js
tweets: [
  "이거 저장각 ㅋㅋㅋㅋ",                        // 계정 기본값(humor)
  { t: "이 떡밥 아직도 안 끝났네", a: "bait" }   // 예외
]
```

- 정규화 함수 하나가 둘 다 `{ text, attr }`로 통일한다.
- **중복 판정의 `src`는 `text`를 그대로 쓴다** — 기존 규칙(치환 전 원문 비교)이 그대로 유지된다.
- 예외는 거의 쓰지 않는다(총 20개 이하 예상). 448개를 건드릴 필요가 없고,
  예외가 시각적으로 튀어서 나중에 읽을 때 의도가 보인다.

## 3. 증가량과 상한

**같은 속성 트윗 5개에 반응할 때마다 그 스탯 +1.** 스탯은 계속 정수다.

소수(+0.2)를 누적하지 않는 이유: 스탯은 지금까지 정수만 다뤘고(`evalFormula`가 `Math.round`),
소수를 들이면 스탯 패널이 `글빨 7.0` `멘탈 50.0`처럼 전부 소수점을 달게 된다.
5회당 +1은 밸런스 영향이 같으면서 화면을 그대로 둔다. 진행이 안 보이는 문제는
반응할 때 뜨는 토스트 게이지가 해결한다(5절).

**트윗 하나는 카운터를 정확히 한 번만 올린다.**

- 좋아요든 리트윗이든 **먼저 누른 쪽**에서 오른다. 나머지 하나는 올리지 않는다.
- **취소해도 되돌리지 않는다.** 이미 읽고 반응한 경험은 사라지지 않는다.
- **다시 눌러도 추가되지 않는다.** 이게 없으면 켜고 끄기로 무한 증식한다.

상태:
```js
state.reacted["tw12"] = { like: true, rt: true, rtDay: 12, gained: true }
state.reactCount = { 글빨: 3, 유머: 0, 감각: 4, 논란성: 1 }   // 0~4, 5가 되면 +1하고 0으로
```
`gained`가 참이면 그 트윗에서는 다시 세지 않는다. `like`/`rt`와 독립이라 취소해도 남는다.
`reactCount`는 옛 세이브에 없으므로 `create()`의 `missing` 맵으로 채운다.

**하루 한도는 없다.** 과거 트윗(계정 발견 시 들어오는 seed 20개)도 대상이다.
16계정 전부 발견하면 320개가 열려 카테고리당 최대 +12~13이 되지만, 전탐색은 지루한 노동인 데다
`bait` 계정에서는 논란성이 함께 쌓인다.

**수식의 실질 상한이 안전장치다.** `clampStat`에 상한은 없지만 `engagement()`가
`Math.min(감각, 40)` / `Math.min(유머, 40)`으로 묶고 글빨은 `글빨/(글빨+20)`이라 체감 감소한다.
반응만으로 조회수를 폭주시킬 수 없다.

5라는 값은 `data/npcs.js`에 노브로 두고 `test/sim.js` 결과를 보고 조정한다.

## 4. 아키텍처

**엔진 (`js/engine.js`)**

`toggleReaction(tweetId, kind)`가 스탯 적용까지 맡는다. 지금은 순수 토글이다.

- 켤 때, 그 트윗의 `gained`가 거짓이면 `reactCount[스탯]`을 +1하고 `gained = true`
- 카운터가 5가 되면 그 스탯 +1, 카운터는 0으로
- 끌 때는 아무것도 하지 않는다
- 반환값에 `gain: { stat, count, leveled }`을 추가한다 — UI가 토스트를 그릴 근거.
  `count`는 현재 카운터(0~4, 오른 직후면 0), `leveled`는 이번에 스탯이 올랐는지.
  이미 `gained`된 트윗이면 `gain`은 `null`이다(토스트를 안 띄운다)
- **하루를 소모하지 않는다.** `advanceTurn`과 무관한 별도 경로 그대로다
- `clampStat`을 거쳐야 한다 — 논란성은 0이 바닥(`clampStat`에 상한은 없다)

속성 결정(카테고리 → 스탯 매핑)은 엔진에 둔다. 아이콘·색 표기는 `ui.js` 몫이다
(날짜를 엔진이 모르는 것과 같은 분리).

**UI (`js/ui.js`)**

- 트윗 우상단에 속성 아이콘. **스탯 패널과 같은 아이콘·색(tone)을 쓴다** —
  유머 아이콘이 양쪽에서 같아야 설명 없이 읽힌다
- 이미 반응해서 `gained`가 된 트윗은 **반투명**으로 흐린다.
  정보는 남으면서 아직 얻을 게 있는 트윗이 눈에 띈다
- NPC 트윗(`kind: "npc"`)에만 붙는다. 내 트윗·답글·이벤트·정산 항목엔 없다

**아이콘 (`js/icons.js`)**

`trending-up`을 PATHS에 추가한다(lucide). 나머지 셋은 이미 있다.

## 5. 반응 토스트

반응해서 카운터가 오를 때, **누른 자리 근처에** 작은 토스트가 뜬다.
게이지가 상시로 화면에 있으면 지저분하고, 없으면 진행이 안 보인다 — 누른 순간에만 보여준다.

**내용:** 속성 아이콘 + 5칸 게이지바 + 스탯 이름. 게이지는 현재 카운터만큼 채워진다.

**동작:**
- **위치는 클릭 지점 근처.** `position: fixed` + 클릭 좌표를 쓴다.
  화면 가장자리에서 잘리지 않게 **안쪽으로 밀어 넣는 보정**을 넣는다(모바일 포함).
- **연타하면 새로 만들지 않는다.** 토스트 하나를 유지한 채 **위치만 새 클릭 지점으로 옮기고**
  게이지를 이어서 올린다. 사라지는 타이머는 리셋된다. 여러 장이 쌓이면 화면을 덮는다.
- **5칸이 다 차면 터지는 연출** + `유머 +1`. 평소보다 조금 더 머물다 사라진다.
- **이미 `gained`된 트윗은 아예 안 띄운다.** 아무 일도 안 일어났는데 뜨면 오해를 부른다.

## 6. 날짜 위치 이동

트윗 날짜를 `.meta`에서 **계정명 옆으로** 옮긴다.

- 현재: 이름/핸들 → 본문 → `.meta`(날짜 + 조회수·좋아요·리트윗)
- 변경: 이름/핸들/**날짜** → 본문 → `.meta`(내 트윗의 수치만)

실제 X와 같은 구조이고, 우상단 속성 아이콘과 시각적으로 분리된다.
`.meta`는 내 트윗에서만 내용이 남는다.

## 7. 검증

**기존 회귀 테스트 넷 전부 통과해야 한다:**
`node test/engine.test.js` / `node test/sim.js` / `node test/check-css.js` / `node test/check-assets.js`

**신규 테스트:**
- 반응하면 속성에 맞는 `reactCount`가 1 오른다
- 같은 속성 5개에 반응하면 그 스탯이 +1 오르고 카운터가 0으로 돌아간다
- 스탯이 정수로 유지된다(소수가 새어 나오지 않는다)
- 취소해도 카운터·스탯이 원복되지 않는다
- 취소 후 다시 눌러도 추가로 세지 않는다
- 좋아요를 준 뒤 리트윗해도 추가로 세지 않는다(트윗당 1회)
- 이미 `gained`된 트윗에 반응하면 `gain`이 `null`이다(토스트를 안 띄운다)
- `reactCount`가 없는 옛 세이브가 `create()`에서 채워진다
- 계정 기본 속성이 `reactsTo[0]`을 따른다
- 트윗 개별 속성이 계정 기본값을 덮어쓴다
- `bait` 트윗이 논란성을 올린다
- 모든 계정의 첫 카테고리가 유효한 매핑을 갖는다 (`check-assets.js`)
- `toggleReaction`이 여전히 날짜를 넘기지 않는다(하루를 소모하지 않는다)

**밸런스:** `test/sim.js`의 네 전략이 전부 100만에 도달해야 한다.

## 결정하지 않은 것 (YAGNI)

- **하루 한도** — 트윗당 1회 상한으로 충분하다고 판단했다
- **좋아요/리트윗 차등** — 트윗당 1회라 구분이 무의미하다
- **스탯 상한 9999로 확대** — `engagement()`의 계수를 전부 다시 잡아야 하고
  조회수→정산금→생활비 경제 축 전체가 재조정된다. 이 기능과 분리해 별도 작업으로 다룬다
- **스탯 소수점 표시** — 5회당 +1로 정수를 유지하기로 해서 필요 없어졌다
- **과거 트윗 차등** — 발견 시 20개가 열리는 건 알고 받아들인 트레이드오프다
- **친밀도 등 계정별 관계 수치** — 별개 기능이다
