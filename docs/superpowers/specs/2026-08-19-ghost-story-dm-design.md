# 괴담계 스토리 DM + 산책 — 설계

날짜: 2026-08-19

## 요약

`@old_records`(옛기록보관) 계정이 조건을 충족한 플레이어에게 먼저 DM을 보내고,
**순서가 있는 이야기**가 시작된다. 이야기 중간에 플레이어는 **산책하기** 행동으로
실제 폐교 앞에 서게 되고, 거기서 한 선택이 이야기의 갈래를 정한다.

기존 DM(선택지 풀)과 다른 새 갈래다. **DM이 처음으로 게임의 핵심 루프와 맞물린다** —
지금까지 DM은 하루를 안 쓰는 곁가지였는데, 이 이야기만은 산책 한 번으로 하루를 쓴다.

## 1. 시작 조건

세 가지가 **모두** 충족된 턴에 확정으로 첫 DM이 도착한다(확률 없음).

| 조건 | 값 | 이야기상 의미 |
|---|---|---|
| `@old_records` 트윗에 반응 | **5개 이상** | 그 계정을 계속 지켜본 사람 |
| 감각 | **>= 12** | 분위기를 느낄 줄 아는 사람 |
| 글빨 | **< 20** | 따지고 들지 않는 사람 |

반응은 좋아요·리트윗 합산이고 트윗당 1회다(`state.reacted[id].gained`와 같은 기준).

**임계값의 근거(실측).** 스탯은 한 축에 집중하면 10일에 18까지 오르고, 안 키우면 5에 머문다
(행동 하나가 한 스탯만 올리는 구조라 그렇다 — `write`=글빨+2, `trend`=감각+2).
그래서 이 조건은 실질적으로 **"감각은 챙겼고 글빨은 안 챙긴"** 플레이어를 고른다.
괴담계는 검증하려 드는 사람이 아니라 덥석 믿어주는 사람을 찾는다.

측정값:
```
감각특화  10일 글5/감18   20일 글5/감28
글빨특화  10일 글18/감5   20일 글28/감5
무성장    10일 글5/감5    20일 글5/감5
```

## 2. 새 행동 — 산책하기

**상시 행동이다.** 스토리와 무관하게 언제든 쓸 수 있고, 스토리가 그 위에 얹힌다.
스토리 전용 행동으로 만들면 이야기가 끝난 뒤 죽은 행동이 된다.

```js
{ id: "walk", label: "산책하기",
  effects: { "멘탈": 8, "감각": 1 },
  tweet: { category: "daily", effects: { "팔로워": "1 + 감각 + 팔로워*0.01" }, templates: [...] } }
```

휴식(멘탈 +15)보다 회복이 약한 대신 감각이 붙는다 — 걸으면서 바깥을 보는 행동이다.

## 3. 흐름

```
[조건 충족]
    ↓
s1 첫 연락 → s2 부탁("게시판 열두 번째 줄만 봐주십시오")
    ↓
[DM 멈춤 — 선택지 없음. 방은 열려 있고 그 아래가 비어 있다]
    ↓
산책하기 (하루 소모) → 폐교 이벤트
    ↓
  ⟨분기 1⟩ 사진을 찍는다 / 눈으로만 본다
    ↓
s4a(2일 뒤) / s4b(즉시) → s5 → s6(3일 뒤)
    ↓
  ⟨분기 2⟩ 아무도 없었다 / 한 사람 있었다
    ↓
끝A(즉시) / 끝B(1일 뒤)
```

**하루를 쓰는 건 산책 한 번뿐이다.** DM 자체는 여전히 하루를 안 쓰고 스탯도 안 건드린다.

### 진행 방식

- 선택지를 고르면 **보통 즉시** 답장이 온다. 한자리에서 이야기가 흐른다.
- 특정 노드는 `delay: N`을 갖는다. 그 답장은 **N일 뒤** 도착한다.
- 기다리는 동안 방은 **열려 있고 아무 표시도 없다.** 내가 보낸 말까지만 보이고 그 아래가 비어 있다.
  답이 오면 DM 뱃지가 뜬다.
  **"기다리는 중" 같은 표시를 넣지 말 것** — 침묵이 연출로 작동하려면 시스템이 설명하면 안 된다.

## 4. 이야기 — 「명단에 없는 이름」

사료 기록체를 유지하되 사적인 자리라 조금 더 무너진다.

**s1 — 첫 연락**
> 제 기록을 계속 보고 계신 것 같아 실례를 무릅쓰고 씁니다.
> 확인을 부탁드릴 것이 하나 있습니다.

선택지: "무슨 일이신가요" / "제가 도울 게 있나요" → 둘 다 s2

**s2 — 부탁** (선택지 없음, 행동 대기)
> 작년에 폐교 명단을 정리하다 없는 이름을 하나 봤다고 적은 적이 있습니다.
> 그 학교가 선생님 동네에 있습니다.
> 지나는 길에 정문 앞 게시판만 한 번 봐주실 수 있겠습니까.
> 게시판에 졸업생 명단이 붙어 있을 겁니다. 열두 번째 줄만 봐주십시오.
>
> 저는 그 동네에 못 갑니다. 이유는 적지 않겠습니다.
> 사진은 찍지 마시고 눈으로만 보십시오.

**[폐교 이벤트 — 산책 중]**
> 산책하다 문 닫힌 학교 앞을 지났다.
> 녹슨 정문 옆 게시판에 빛바랜 졸업생 명단이 붙어 있다.

⟨분기 1⟩ **사진을 찍어둔다** → s4a / **눈으로만 확인한다** → s4b

**s4a — 어긴 쪽** `delay: 2`
> 찍지 말라고 했습니다.
> …아니요, 제가 예민했습니다. 사진은 잘 받았습니다.
> 열두 번째 줄에 뭐라고 적혀 있었습니까.

**s4b — 지킨 쪽** (즉답)
> 감사합니다. 그렇게 해주십시오.
> 열두 번째 줄에 뭐라고 적혀 있었습니까.

둘 다 → s5

**s5 — 합류**
> 그 이름이 제가 본 것과 같습니다.
> 그런데 선생님, 명단은 스물세 명이었습니까.

선택지: "세어보진 않았어요" / "스물세 명 맞았어요" → 둘 다 s6

**s6 — 어긋남** `delay: 3`
> 제가 가진 기록에는 스물두 명입니다.
> 십오 년 전에 제가 직접 세었습니다.
>
> 하나 여쭙겠습니다. 게시판 앞에 선생님 말고 다른 사람이 있었습니까.

⟨분기 2⟩ **"아무도 없었어요"** → s7a / **"한 사람 있었던 것 같아요"** → s7b

**끝 A — s7a** (즉답)
> 그렇습니까. 다행입니다.
>
> 이 기록은 여기서 닫겠습니다. 도와주셔서 감사합니다.
> 앞으로 그 동네 이야기가 올라오거든, 저에게는 알리지 말아주십시오.
>
> 확인된 것은 여기까지입니다.

**끝 B — s7b** `delay: 1`
> 그 사람 얼굴을 기억하십니까.
>
> …아닙니다. 대답하지 않으셔도 됩니다.
> 십오 년 전에도 저는 혼자가 아니었습니다.
>
> 명단은 앞으로도 한 명씩 늘 겁니다. 세지 마십시오.
> 이 기록은 닫지 않겠습니다.

### 설계 의도

- **분기 1(사진)** 은 성격을 가른다. 어긴 쪽은 이틀 침묵 뒤 상대가 한 번 무너졌다 수습한다 —
  이 계정이 감정을 드러내는 유일한 순간이다. 이야기는 같은 곳으로 가되 상대가 어떤 사람인지가 달라진다.
- **분기 2(사람)** 는 결말을 가른다. 끝 A는 닫히고 끝 B는 열린 채 남는다.
  "이 기록은 닫지 않겠습니다"가 계정 컨셉("사실 여부는 판단하지 않습니다")과 맞물린다.
- **지연 세 곳**(2일 / 3일 / 1일)이 리듬을 만든다. s6의 사흘이 가장 길다 —
  숫자가 어긋났다는 걸 확인하러 간 시간이라 침묵에 이유가 있다.
- **핵심 장치는 스물두 vs 스물세**다. 플레이어가 세어봤든 안 세어봤든 상대의 기록과 어긋나고,
  그 한 명이 누구인지는 끝까지 말하지 않는다.

## 5. 데이터 구조

`data/dms.js`에 **새 갈래**를 만든다. 기존 `topics`(선택지 풀) 방식과 섞지 않는다 —
하나는 순서가 없고 하나는 순서가 전부라 같은 구조에 넣으면 규칙이 엉킨다.

```js
GAME_DATA.dm.stories = {
  "@old_records": {
    requires: { reactions: 5, "감각": ">=12", "글빨": "<20" },
    start: "s1",
    nodes: {
      "s1": { text: "…", choices: [{ say: "무슨 일이신가요", to: "s2" }, …] },
      "s2": { text: "…", choices: [] },                    // 대기 (행동을 기다린다)
      "s4a": { text: "…", delay: 2, choices: [{ say: "…", to: "s5" }] },
      "s7a": { text: "…", choices: [], end: true }         // 끝
    }
  }
};
```

**`choices`가 비면 대기 또는 끝이다.** 둘을 가르는 건 `end: true`다 —
플래그가 없으면 대기(무언가 다른 것이 진행시킨다), 있으면 이야기 종료다.

## 6. 폐교 이벤트

`data/events.js`에 추가한다. 기존 이벤트는 전부 확률로 알아서 발동하는데,
이건 **행동에 걸린 확정 이벤트**다.

```js
{ id: "old_school",
  trigger: { dmStory: "@old_records:s2", action: "walk" },   // chance 없음 = 확정
  stages: [{
    feed: ["산책하다 문 닫힌 학교 앞을 지났다.\n녹슨 정문 옆 게시판에 빛바랜 졸업생 명단이 붙어 있다"],
    choices: [
      { label: "사진을 찍어둔다", story: "@old_records:s4a", … },
      { label: "눈으로만 확인한다", story: "@old_records:s4b", … }
    ] }] }
```

`trigger`에 두 가지가 새로 필요하다:
- **`dmStory`** — `"핸들:노드"` 형식. 그 스토리가 그 노드에 있을 때만
- **`action`** — 그 행동을 했을 때만

선택지의 **`story`** 필드가 DM 스토리를 그 노드로 진행시킨다.

이 셋은 **범용 노브**로 만든다 — 나중에 다른 계정 이야기도 다른 행동에 걸 수 있어야 한다.

## 7. 상태

```js
state.dmStory = {
  "@old_records": { node: "s3", pending: { to: "s4a", day: 12 }, done: false }
}
```

- `node` — 지금 어느 노드인가
- `pending` — 지연 답장이 걸려 있으면 `{ to, day }`. 그 날짜가 되면 도착한다
- `done` — 끝 노드에 도달했는가. 참이면 다시 시작하지 않는다

옛 세이브에는 없으므로 `create()`의 `missing` 맵이 채운다(최상위 필드라 자동).

## 8. 엔진

- **계정별 반응 수를 세는 함수.** `state.reacted`엔 트윗 id만 있어서
  어느 계정 트윗인지는 보관함(`npcTweets`)을 봐야 안다.
- `advanceTurn`에서 순서대로:
  1. 시작 조건 확인 → 충족하면 `start` 노드 도착
  2. `pending` 날짜 도달 확인 → 도달하면 그 노드 도착
  3. 행동 이벤트 발동 확인 (`trigger.action`이 이번 행동과 같고 `dmStory`가 맞으면)
- **스토리 진행 중인 계정은 기존 확률 DM 후보에서 뺀다** — 이야기 중간에 잡담이 끼면 안 된다.
- 스토리 선택은 **하루를 안 쓰고 스탯도 안 건드린다**(기존 DM 규칙과 같다).
  하루를 쓰는 건 산책이라는 행동뿐이다.

## 9. UI

기존 대화방(`#view-dm`)을 그대로 쓴다.

- 선택지 바(`.dm-choices`)에 스토리 선택지를 그린다. 기존 `topics` 선택지와 같은 모양이다.
- **대기 중이면 아무것도 안 그린다.** 설명 문구도 없다.
- 지연 답장이 도착하면 DM 뱃지가 뜬다(기존 `unreadDms` 경로 그대로).

## 10. 검증

- 조건 미충족(반응 부족 / 감각 낮음 / 글빨 높음)이면 시작 안 됨
- 세 조건 충족 시 그 턴에 확정 도착
- s2에서 선택지가 없고, 산책해야 진행된다
- 폐교 이벤트가 **스토리 s2일 때만** 발동 (다른 노드·스토리 없음에선 안 뜬다)
- 폐교 이벤트가 **산책 중에만** 발동 (다른 행동에선 안 뜬다)
- 분기 1 둘이 각각 s4a/s4b로 가고 s5에서 합류
- 분기 2 둘이 각각 다른 끝으로 간다
- `delay: N`이 정확히 N일 뒤 도착 (하루 일찍/늦게 아님)
- 멘탈 붕괴로 이틀이 건너뛰어도 지연이 어긋나지 않는다
- 끝 도달 후 `done`이 참이고 다시 시작되지 않음
- 스토리 진행 중 그 계정의 확률 DM이 안 온다
- 산책하기가 스토리와 무관하게 상시 동작한다
- 옛 세이브에 `dmStory`가 없어도 동작
- 기존 5계정 DM이 영향받지 않음
- 스토리 선택이 하루를 안 쓴다

## 결정하지 않은 것 (YAGNI)

- **다른 계정의 스토리** — 구조는 범용으로 만들되 지금은 괴담계 하나만 쓴다
- **스토리 보상(스탯·팔로워)** — DM은 스탯을 안 건드린다는 기존 규칙을 유지한다.
  보상을 붙이려면 그 규칙부터 다시 논의해야 한다
- **끝 B의 후속** — "이 기록은 닫지 않겠습니다"는 여운이지 예고가 아니다
- **분기를 더 늘리는 것** — 두 곳이면 충분하고, 늘리면 분량이 배로 뛴다
