# 인용 트윗과 트윗 삭제

날짜: 2026-08-20

## 배경

기존에 남의 트윗에 할 수 있는 건 좋아요·리트윗뿐이고 둘 다 하루를 안 쓴다.
내 트윗은 올린 뒤 아무것도 할 수 없다. 여기에 둘을 더한다.

- **인용** — 타임라인을 읽는 행위가 곧 행동 선택이 된다. 지금 컴포즈는 "행동 11개 중
  하나 고르기"라 대상이 없는데, 인용은 처음으로 "무엇을 트윗할까"에 대상을 준다.
- **삭제** — 논란성이 지금은 오르기만 하고 내려가는 경로가 사실상 없다.
  사이버렉카 엔딩(논란성 300)이 사고로 걸리면 되돌릴 수 없다.

**예약 트윗은 하지 않는다.** 검토했고 제외하기로 확정했다.

## 1. 인용 트윗

### 진입점

남의 트윗 리트윗 버튼 → 메뉴에 `인용하기` 추가. 지금 메뉴엔 `재게시`/`재게시 취소`만 있다.
실제 X와 같은 자리이고, 메뉴가 이미 있어서 새 자리를 안 만들어도 된다.

트윗 고르는 화면을 따로 만들지 않는다 — 그 화면은 결국 타임라인을 다시 그리는 것이라 중복이다.

### 하루를 쓴다

**리트윗·좋아요와 다르다.** 내 트윗을 새로 쓰는 일이라 `advanceTurn`을 지난다.
따라서 정산·이벤트·엔딩 판정이 전부 정상 동작한다.

### 결과 — 원본 트윗의 속성으로 갈린다

속성은 반응 스탯과 같은 축을 쓴다(`attrStat`: humor / info / daily / bait).

| 원본 속성 | 팔로워 | 논란성 | 멘탈 | 부수 |
|---|---|---|---|---|
| bait | `팔로워*0.05 + 80` | **+8** | -5 | - |
| humor | `팔로워*0.03 + 50` | +1 | -2 | - |
| info | `팔로워*0.02 + 40` | 0 | -2 | 글빨 +1 |
| daily | `팔로워*0.015 + 25` | 0 | -1 | - |

**핵심은 bait 인용이다.** 지금 논란성을 크게 올리는 경로는 `떡밥 지켜보기` 행동 하나뿐인데,
인용이 생기면 "저 트윗을 저격할까"라는 구체적 유혹이 타임라인에 매일 흐른다.
논란성 300을 넘으면 사이버렉카 엔딩이라 진짜 도박이 된다.

**+8로 잡은 근거**: 40번 인용해야 300이다. 사이버렉카를 노리면 갈 수 있고 몇 번 실수로는
안 걸린다. 기존 실측(반응 그라인딩 233 / 어그로 740) 사이 구간이 유지되는지
`sim.js`에 `인용저격` 전략을 추가해 재고, 안 맞으면 조정한다.

세기는 기존 행동과 맞췄다 — `떡밥 지켜보기`가 `팔로워*0.06`으로 제일 세고 나머지는 1~1.5%다.
bait 인용(5%)이 그 바로 아래에 온다.

### 표시

내 타임라인·프로필에 **인용 카드**로 뜬다. 원본이 안에 박스로 들어간 형태(실제 X와 동일).
조회수가 붙어서 **정산 대상**이다.

### 엔진 API

`quoteTweet(tweetId)` — 대상이 없거나 `kind !== "npc"`면 `null`.

## 2. 트윗 삭제

### 진입점

내 트윗의 `⋯` 메뉴 → `삭제`. 지금 내 트윗에는 메뉴가 없어서 새로 만든다.
`confirm()`을 한 번 받는다 — 되돌릴 수 없다(로그아웃과 같은 규칙).

### 하루를 안 쓴다

반응·팔로우·DM과 같은 부류다.

### 효과

- `tweetLog`와 `feed`에서 **완전히 제거**한다. 묘비(`deleted: true`)를 남기지 않는다.
  정산이 `tweetLog`를 훑어 계산하므로 **그 트윗 조회수가 정산에서 자동으로 빠진다** —
  정산 로직을 건드릴 필요가 없다.
- **논란성 -5**
- 확률로 **박제 이벤트** — "지웠는데 캡처가 돈다". 논란성 **+10**(지운 것보다 더 오른다).

**지우는 게 항상 이득이면 그냥 버튼이지 결정이 아니다.** 돈(조회수)과 박제 리스크가
걸려야 진짜 선택이 된다. 이미 있는 `@rookie_writer`(쓰다가지움 — 매일 쓰고 매일 지웁니다)와
세계관도 맞물린다.

### 엔진 API

`deleteTweet(tweetId)` → `{ id, views, mood, busted }` 또는 `null`.

## 노브

로직에 하드코딩하지 않고 데이터 파일에 둔다(기존 규칙).
인용 수치와 박제 확률 둘 다 해당한다.

## 건드리지 않는 것

- `engagement()` 수식 — 조회수 계산은 그대로다. 삭제는 이미 계산된 값을 빼는 것뿐이다.
- `advanceTurn`의 정산 로직 — `tweetLog`를 훑는 방식이라 삭제가 자동 반영된다.
- 예약 트윗.

## 검증

`test/engine.test.js`에 회귀 테스트를 추가한다:

- 인용이 하루를 쓰는가 / 속성별로 다른 효과가 나오는가
- 인용 대상이 아닌 것(내 트윗·답글·없는 id)에 `null`인가
- 삭제가 하루를 **안** 쓰는가
- 삭제한 트윗의 조회수가 정산에서 빠지는가
- 없는 id 삭제에 `null`인가

`test/sim.js`에 `인용저격` 전략을 추가해 논란성이 233~740 사이인지 실측한다.

기존 4종(`check-assets` / `check-css` / `engine.test` / `sim`)이 전부 통과해야 한다.
